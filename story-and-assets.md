# Story and asset mapping

Use a compact mapping before implementation:

| Content | Source | Role | Action | Result | Approval |
| --- | --- | --- | --- | --- | --- |
| Main couple photo | User-supplied photo | Memory | Open album | Large photo and caption | Preserve framing |
| Couple sticker | Approved identity/sprite sheet | Frame accent | None by default | Static decoration | Confirm chosen poses |
| Gift image | Supplied object image | Present | Open box | Reveal actual gift | Preserve actual object |
| Travel wish | User's future destination | Future | Select map marker | Imagined scene | Never label as past trip |

Do not embed private source paths, real correspondence or identifying captions in a public example. Use fictional names and synthetic example images for reusable demonstrations.

## Design choices with consequences

- A central setting reduces disconnected pages, but requires visible entry points. Provide labels and a plain navigation alternative.
- Real photos carry the emotional weight; decorative characters should not reduce them to thumbnails.
- Character rendering and room rendering need compatible proportions, materials and light, not necessarily identical realism.
- Dense destinations on a world map need displaced labels with leader lines. Preserve the actual anchor coordinates and separate the label from the location marker.
- Audio must remain optional. Start through a user gesture, provide pause/resume, retain the user's mute choice and avoid audio suddenly restarting after modal changes.

## Representative approval views

For an end-to-end redesign, choose scenes that expose the actual visual decisions: an entry or home scene, a real-photo layout, and one interaction close-up. Mark them as concept images if controls do not yet work.
